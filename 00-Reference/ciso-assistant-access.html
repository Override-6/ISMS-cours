2. First sign-in

Each instance has its own password, in the column above. The login is the same everywhere: admin@lockbay.eu. This account is for getting in once, not for working.

  1. Open your group's address and sign in with the password on your row.
  2. Create a personal, named account in Identity management, then give it the necessary rights on the subsidiary's domain.
  3. Sign out and carry on working with that account. Everything produced must be attributable: that is the rule this module teaches, and it starts here.
  4. Change the bootstrap password once the account is created. It is written on a sheet handed out in class, so it protects nothing.

3. The other route: a personal instance

CISO Assistant is open source software published by intuitem. A personal deployment replaces the provided instance without penalty; the project's documentation gives the procedure. Both routes produce the same work and the same exported evidence of state.

4. What goes in, and what does not

High availability, medium integrity, low confidentiality. This is not a production tool, and its environment is shared.

Only the MERIDIAN case, which is fictional, goes in. No real data, no person's name, nothing from an internship or an employer. Rating the confidentiality of a tool before pouring anything into it is exactly the reflex this module installs: it applies here first.

5. If something breaks

A missing teammate, a stubborn computer or a temperamental network are part of the job. Each group finds its own way through; the other route is one. An incident gets reported, it does not get waited out.
